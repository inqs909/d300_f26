Connecting to Databases

A database can contain many related tables. Usually, we:

  1. Open a connection to the database.
  2. Ask the database for specific data.
  3. Receive the result as a local data frame.
  4. Close the connection when finished.

A connection alone does not copy every table into R or Python.

Fictional movie-rental database

Download movies_rentals.sqlite

Table One row represents Key fields Rows
customer One customer customer_id 8
film One film film_id 6
rental One rental of one film rental_id, customer_id, film_id 16

rental.customer_id references customer.customer_id.

rental.film_id references film.film_id.

Columns Used

Table Columns and meaning
customer customer_id, first_name, last_name, city
film film_id, title, rating, length in minutes
rental rental_id, customer_id, film_id, rental_date, return_date, amount paid in dollars

Dates use ISO text: YYYY-MM-DD. A missing return_date means the film has not been returned.

R packages

Run installation once in the R console:

install.packages(
  c("DBI", "RSQLite", "dplyr", "dbplyr")
  )

Load packages in each new R session:

library(DBI)

DBI defines the common database interface. RSQLite supplies the SQLite driver. We will use dplyr and dbplyr later.

R: Connecting the database

con <- dbConnect(
  RSQLite::SQLite(),
  "~/Downloads/movie_rentals.sqlite",
  flags = RSQLite::SQLITE_RO
  )
1
The main function to interface with the database
2
Specify the type of DBMS being used
3
Location of the database
4
Indicates that the database is Read-Only

con is a connection object. No table has been imported yet.

R: discovering tables and columns

dbListTables(con)

dbListFields(con, "film")

dbGetQuery(con, "PRAGMA table_info(film)")

dbListFields() lists column names. SQLite’s PRAGMA table_info also reports declared types and key information.

Inspect an unfamiliar database before writing a query.

R: importing a complete table

films <- dbReadTable(con, "film")
head(films)
str(films)
nrow(films)
1
Copy every row and column of film into an R data frame.

This is convenient for a small table. A large table can exceed the available memory.

R: importing a SQL query result

sql <- "
  SELECT film_id, title, rating, length
  FROM film
  WHERE length >= 100
  ORDER BY length DESC, film_id
"
long_films <- dbGetQuery(con, sql)
long_films
1
Execute the SQL and return its result as a data frame.

R: using parameters

selected_rating <- "PG-13"

rated_films <- dbGetQuery(
  con,
  "SELECT title, length FROM film
   WHERE rating = ? ORDER BY film_id",
  params = list(selected_rating)
)
1
? marks a value to supply separately.
2
RSQLite binds the supplied rating to that placeholder.

R: joining tables in the database

rental_details <- dbGetQuery(con, "
  SELECT r.rental_id, c.first_name, f.title,
         r.rental_date, r.amount
  FROM rental AS r
  JOIN customer AS c ON r.customer_id = c.customer_id
  JOIN film AS f ON r.film_id = f.film_id
  ORDER BY r.rental_id
")
head(rental_details)

One SQL query can combine tables without first importing each table separately.

Closing a Connection

After finishing the SQLite examples and activities:

dbDisconnect(con)

Python packages

Run installation in a terminal for your chosen Python environment:

python -m pip install pandas

In your Python session:

import sqlite3
import pandas as pd

sqlite3 normally come with Python. pandas provides data frames and SQL-reading functions.

Python: the database path

import sqlite3

conn = sqlite3.connect(
    "file:~/Downloads/movie_rentals.sqlite?mode=ro",
    uri=True
    )
1
Functions used to connect to a database.
2
Convert the path to a file URI and request read-only access.
3
Tell sqlite3 to interpret the string as a URI.

con holds an open connection. This step does not create a pandas DataFrame.

Python: discovering tables

tables = pd.read_sql_query(
  """
    SELECT name
    FROM sqlite_schema
    WHERE type = 'table' AND name NOT LIKE 'sqlite_%'
    ORDER BY name
  """, 
  conn)
print(tables)

sqlite_schema describes objects stored in a SQLite database. This discovery query is specific to SQLite.

Python: importing a complete table

films = pd.read_sql_query(
  "SELECT * FROM film", 
  conn
)
print(films.head())
print(films.shape)
films.info()

SELECT * requests every column. Without a WHERE clause, this query returns every row.

films is now a local pandas DataFrame with 6 rows and 4 columns.

Python: importing selected rows

sql = 
  """
    SELECT film_id, title, rating, length
    FROM film
    WHERE length >= 100
    ORDER BY length DESC, film_id
  """
long_films = pd.read_sql_query(sql, conn)
print(long_films)

The SQL is identical to the R example. Only the code that submits it changes.

Python: using parameters

selected_rating = "PG-13"
rated_films = pd.read_sql_query(
    """
      SELECT title, length FROM film
      WHERE rating = ? ORDER BY film_id 
    """,
    conn,
    params=(selected_rating),
)
1
SQLite uses ? for a positional value placeholder.
2
Supply a tuple of values. The comma creates a one-element tuple.

Expected titles: Orbit Nine, City of Stars.

Python: joining tables

rental_details = pd.read_sql_query(
  """
    SELECT r.rental_id, c.first_name, f.title,
           r.rental_date, r.amount
    FROM rental AS r
    JOIN customer AS c ON r.customer_id = c.customer_id
    JOIN film AS f ON r.film_id = f.film_id
    ORDER BY r.rental_id
  """, 
  conn, 
  parse_dates=["rental_date"])
print(rental_details.head())

parse_dates asks pandas to convert the returned date column to a datetime representation.

Close Connection

conn.close()

Database work and local work

Operation Where it happens
WHERE, JOIN, GROUP BY in SQL In the database engine
dbGetQuery() / pd.read_sql_query() Submit SQL and transfer returned data
mean(films$length) In the R session
films["length"].mean() In the Python session

SQLite runs locally in this lecture. With a database server, database work happens on the server and results travel over the connection.

Smaller results reduce transfer and memory

Suppose rental contains 50 million rows and you need monthly totals.

SELECT SUBSTR(rental_date, 1, 7) AS month,
       COUNT(*) AS n_rentals,
       ROUND(SUM(amount), 2) AS revenue
FROM rental
GROUP BY SUBSTR(rental_date, 1, 7)
ORDER BY month;

Import the summary instead of all 50 million rental records.

The database may still need to scan many records to compute it. The result transferred to R or Python is much smaller.

R: lazy database with dbplyr

library(dplyr)
library(dbplyr)

film_db <- tbl(con, "film")
long_query <- film_db |>
  filter(length >= 100) |>
  select(title, length) |>
  arrange(desc(length), title)
show_query(long_query)
1
Create a reference to a database table.
2
Display the SQL generated from the dplyr operations.

tbl() does not import the whole table. Printing a lazy table can run a limited preview query.

R: collect retrieves the result

long_films_local <- long_query |> collect()
class(long_films_local)
# A local tibble/data frame

Before collect(), long_query describes database work. collect() executes the query and brings its results into R.

Filter, select, and summarize before collecting a large result. Database backends support different translations of R functions.

This is a database-backed dplyr example. It is not a promise that every arbitrary R function can run inside SQL. Use show_query() and backend documentation when a translation fails.
