The three decisions in a pivot

For a report of monthly sales by country:

Decision Example SQL role
What identifies a row? Country and year GROUP BY
Which categories become columns? January, February, March CASE WHEN conditions
What fills each cell? Total sales SUM(Total)

The grain describes what one row represents. Adding year to the row keys keeps January in different years separate.

Pivot and unpivot in SQLite

SQLite has no built-in PIVOT or UNPIVOT operators.

Transformation SQLite approach
Pivot GROUP BY with SUM(CASE WHEN ... END)
Pivot, alternative An aggregate with FILTER (WHERE ...)
Unpivot One SELECT per source column, combined with UNION ALL

A pivot query has a fixed set of output columns. New category values do not automatically create new columns.

Chinook: the first pivot

Database: Chinook

SELECT BillingCountry,
       strftime('%Y', InvoiceDate) AS sales_year,
       ROUND(SUM(CASE WHEN strftime('%m', InvoiceDate) = '01'
                      THEN Total ELSE 0 END), 2) AS Jan,
       ROUND(SUM(CASE WHEN strftime('%m', InvoiceDate) = '02'
                      THEN Total ELSE 0 END), 2) AS Feb,
       ROUND(SUM(CASE WHEN strftime('%m', InvoiceDate) = '03'
                      THEN Total ELSE 0 END), 2) AS Mar
FROM Invoice
GROUP BY BillingCountry, sales_year
ORDER BY BillingCountry, sales_year;
1
Keep country and year as the row keys.
2
Each conditional sum fills one month column.
3
Combine invoices into one row for each observed country/year pair.

All invoices remain in the input, so a country/year with only later sales still appears with three zeros.

Reading a pivot result

BillingCountry sales_year Jan Feb Mar
Canada 2025 30 20 0

Illustrative row, not actual Chinook output.

  • Jan = 30 represents the sum of January invoice totals.
  • The columns contain amounts, not invoice counts.
  • Mar = 0 can mean no March invoices under our zero-filling rule.
  • A country/year with no invoices at all will not appear.

To include entirely absent groups, start with a complete list of desired row keys and use a LEFT JOIN.

Chinook: counting instead of summing sales

Database: Chinook

SELECT strftime('%Y', InvoiceDate) AS sales_year,
       SUM(CASE WHEN strftime('%m', InvoiceDate) = '01'
                THEN 1 ELSE 0 END) AS Jan_invoices,
       COUNT(CASE WHEN strftime('%m', InvoiceDate) = '02'
                  THEN 1 END) AS Feb_invoices
FROM Invoice
GROUP BY sales_year
ORDER BY sales_year;
1
Sum one for each matching invoice and zero for each nonmatch.
2
COUNT(expression) counts non-NULL values. Without ELSE, nonmatches produce NULL.

Pitfall: COUNT(CASE WHEN ... THEN 1 ELSE 0 END) counts both ones and zeros.

Chinook: the FILTER alternative

Database: Chinook

SELECT BillingCountry,
       strftime('%Y', InvoiceDate) AS sales_year,
       ROUND(COALESCE(SUM(Total) FILTER (
         WHERE strftime('%m', InvoiceDate) = '01'
       ), 0), 2) AS Jan,
       ROUND(COALESCE(SUM(Total) FILTER (
         WHERE strftime('%m', InvoiceDate) = '02'
       ), 0), 2) AS Feb
FROM Invoice
GROUP BY BillingCountry, sales_year
ORDER BY BillingCountry, sales_year;
1
FILTER restricts the input to this aggregate without removing the group.
2
SUM returns NULL when it has no non-NULL inputs. COALESCE(..., 0) supplies zero.

Optional syntax: SQLite 3.30.0+. The CASE approach remains the main method for this lecture.

Zero, NULL, and absent groups

Situation Meaning Treatment
Known value of zero Measured amount is zero Keep zero
Missing or unknown measurement Value is unknown Usually keep NULL
No transactions for a displayed cell No matching invoices Zero may suit a sales report
No source rows for a row key Group is absent Build a complete group list if needed

ELSE 0 and COALESCE are reporting choices. They do not prove that missing information is a measured zero.

For a conditional average, use AVG(CASE WHEN ... THEN Total END). Adding ELSE 0 would include nonmatches in the denominator.

Northwind: unpivot with UNION ALL

Database: Northwind

SELECT ProductID, ProductName,
       'In stock' AS inventory_status,
       UnitsInStock AS units
FROM Products
UNION ALL
SELECT ProductID, ProductName,
       'On order' AS inventory_status,
       UnitsOnOrder AS units
FROM Products
ORDER BY ProductID, inventory_status;
1
Convert the original column meaning into a text value.
2
Stack both result sets and preserve every generated row.
3
Use the same column order and compatible types in both branches.
4
Sort the complete combined result. Keep the product ID in both branches.

UNION ALL and missing values

  • Every branch must return the same number of columns in the same logical order.
  • The first SELECT determines the output column names.
  • UNION ALL retains all generated rows. UNION removes exact duplicates.
  • This unpivot keeps zero values and NULL values.
  • With two branches and no filters, N products produce 2N rows.

Preserve ProductID. Different products can share a name.

Source: https://sqlite.org/lang_select.html, compound SELECT statements.

Northwind: pivoting inventory back

Database: Northwind

SELECT ProductID, ProductName,
       MAX(CASE WHEN inventory_status = 'In stock'
                THEN units END) AS UnitsInStock,
       MAX(CASE WHEN inventory_status = 'On order'
                THEN units END) AS UnitsOnOrder
FROM lecture_inventory_long
GROUP BY ProductID, ProductName
ORDER BY ProductID;
1
With exactly one value per product/status, MAX retrieves that value. Missing values stay NULL.
2
Group by the product identifier and its label to restore one row per product.

MAX is appropriate here because each product/status pair is unique. Check uniqueness before using it to reshape other data.

Common mistakes

Mistake Result Correction
Grouping by month while creating month columns Separate rows for months Group by the intended row keys
Omitting year unintentionally Same months across years combine Keep year among the keys
COUNT(CASE ... ELSE 0 END) Nonmatches count too Use SUM of 1/0 or omit ELSE
Dropping product identifiers Different products may combine Retain ProductID
Summing order totals after joining lines Repeated amounts inflate totals Aggregate at the correct grain
Summing already-rounded cells Small discrepancies Round after the final sum

Solution 2: Chinook invoice counts

Database: Chinook

SELECT strftime('%Y', InvoiceDate) AS sales_year,
       SUM(CASE WHEN strftime('%m', InvoiceDate) = '04'
                THEN 1 ELSE 0 END) AS Apr_invoices,
       SUM(CASE WHEN strftime('%m', InvoiceDate) = '05'
                THEN 1 ELSE 0 END) AS May_invoices,
       SUM(CASE WHEN strftime('%m', InvoiceDate) = '06'
                THEN 1 ELSE 0 END) AS Jun_invoices,
       SUM(CASE WHEN strftime('%m', InvoiceDate)
                     IN ('04', '05', '06')
                THEN 1 ELSE 0 END) AS Q2_invoices
FROM Invoice
GROUP BY sales_year
ORDER BY sales_year;
1
One result row represents one invoice year.
2
Each matching invoice contributes one to its month.
3
The Q2 condition covers exactly the three displayed months.

Solution 2: interpretation and check

For every year:

Apr_invoices + May_invoices + Jun_invoices = Q2_invoices

The month conditions are mutually exclusive, and together they cover Q2.

Grouping only by month would combine the same month across different years. It would create a monthly summary with a different grain.

All invoice years remain in the query. A year with no Q2 invoices receives four zeros.

Solution 4: why row counts can differ

The earlier long summary contains only country/year/month combinations with invoices.

The pivot contains every country/year found anywhere in Invoice. Unpivoting its three month columns generates three rows for each of those pairs.

Consequently, the unpivoted result can include explicit zero rows that were absent from the original summary.

The totals agree, but neither the row count nor the individual invoice detail must match. Unpivoting does not reverse aggregation.

Solution 5: joined order-line revenue

Database: Northwind

DROP VIEW IF EXISTS temp.lecture_order_lines;
CREATE TEMP VIEW lecture_order_lines AS
SELECT c.CategoryID, c.CategoryName, o.ShipCountry,
       d.UnitPrice * d.Quantity * (1 - d.Discount)
         AS line_revenue
FROM Orders AS o
JOIN "Order Details" AS d ON o.OrderID = d.OrderID
JOIN Products AS p ON d.ProductID = p.ProductID
JOIN Categories AS c ON p.CategoryID = c.CategoryID;
1
Calculate revenue from the price, quantity, and discount on each order line.
2
Quote the table name because it contains a space.
3
Add each product’s category without changing the order-line grain.

Solution 5: revenue pivot with a CTE

Database: Northwind

WITH country_groups AS (
  SELECT CategoryID, CategoryName, line_revenue,
         CASE WHEN ShipCountry IN ('USA', 'Germany')
              THEN ShipCountry ELSE 'Other' END AS country_group
  FROM lecture_order_lines
)
SELECT CategoryID, CategoryName,
       ROUND(SUM(CASE WHEN country_group = 'USA'
                      THEN line_revenue ELSE 0 END), 2) AS USA,
       ROUND(SUM(CASE WHEN country_group = 'Germany'
                      THEN line_revenue ELSE 0 END), 2) AS Germany,
       ROUND(SUM(CASE WHEN country_group = 'Other'
                      THEN line_revenue ELSE 0 END), 2) AS Other,
       ROUND(SUM(line_revenue), 2) AS total_revenue
FROM country_groups
GROUP BY CategoryID, CategoryName
ORDER BY CategoryID;
1
Classify every line, including a NULL shipping country, into one of three groups.
2
Sum line revenue once into exactly one country column.
3
Keep the category identifier and label as row keys.

Solution 5: interpretation and join grain

Before rounding, USA + Germany + Other equals total_revenue for each category.

Independently rounded columns can differ slightly from a separately rounded total.

An order with three detail rows appears three times after the join. Summing its order-level Freight at that point would count freight three times.

Compute an order-level measure once per order, or define an explicit allocation to order lines before summarizing by category.

The inner joins include categories with matching order lines. Categories with no matching sales are absent.
