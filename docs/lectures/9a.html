Text values, cleaning, extraction, and search

Text literals and identifiers

SELECT 'Ada' AS first_name,
       'O''Brien' AS last_name,
       'Data 300' AS "course label";
1
Single quotes create a text value.
2
Two adjacent apostrophes represent one apostrophe.
3
Double quotes delimit an identifier, including an alias with a space.

NULL, '', and 'NULL' are three different values.

Text, numbers, and missing values

SELECT typeof('007') AS text_type,
       typeof(7) AS number_type,
       length('') AS empty_length,
       length(NULL) AS missing_length;
text_type number_type empty_length missing_length
text integer 0 NULL

Store phone numbers, postal codes, and identifiers as text when leading zeros matter.

Use IS NULL to test missingness. = NULL does not evaluate to true.

Concatenation with ||

SELECT CustomerId,
       FirstName || ' ' || LastName AS customer_name
FROM Customer
ORDER BY CustomerId;
1
|| joins text expressions in the order written.

'Data ' || '300' gives Data 300.

'Data ' + '300' performs numeric conversion and addition. In this example it gives 300.

NULL-aware labels

SELECT CustomerId,
       FirstName || ' ' || LastName AS customer_name,
       COALESCE(NULLIF(trim(Company), ''),
                'Individual') AS customer_type
FROM Customer
ORDER BY CustomerId;
1
trim() removes surrounding spaces, NULLIF(..., '') converts blanks to NULL, and COALESCE() provides a fallback.

Most string functions propagate NULL. text || NULL produces NULL.

ifnull(x, fallback) is the two-argument alternative to coalesce().

concat() and concat_ws() · SQLite 3.44+

SELECT concat('Ana', NULL, 'Rivera') AS joined,
       concat_ws(' ', 'Ana', NULL, 'Rivera') AS spaced;
joined spaced
AnaRivera Ana Rivera
  • These functions skip NULL values among the values being joined.
  • concat_ws() places the separator between retained values.
  • Empty strings are retained and can create extra separators.
  • All NULL value arguments give ''. A NULL separator gives NULL.

Case conversion and Unicode

SELECT lower('DATA 300') AS lower_case,
       upper('Data 300') AS upper_case,
       upper('é') AS accented_letter;

Expected: data 300, DATA 300, and é with the standard built-in functions.

lower() and upper() handle ASCII case conversion by default. They do not provide full Unicode case folding or accent removal.

For multilingual matching, define a normalization policy and use an appropriate extension or application layer.

How long is a string?

SELECT length('café') AS code_points,
       length(CAST('café' AS BLOB)) AS utf8_bytes;
1
In the supplied UTF-8 database, the results are 4 and 5.
  • length(TEXT) counts Unicode code points before the first NUL character.
  • length(BLOB) counts bytes.
  • A visible symbol can contain multiple code points.
  • octet_length() counts text bytes directly in SQLite 3.43+.

Character count, visible-symbol count, and byte count can differ.

Extracting with substr()

SELECT substr('SQLite', 1, 3) AS first_three,
       substr('SQLite', 4) AS from_four,
       substr('SQLite', -3) AS last_three;
1
Start at position 1 and take three characters: SQL.
2
Omit the length to continue to the end: ite.
3
A negative start counts from the right: ite.

substring() is an alias in SQLite 3.34+. Prefer positive lengths for clear classroom code.

Finding a delimiter with instr()

SELECT instr('ana@example.edu', '@') AS at_position,
       instr('ana.example.edu', '@') AS missing_at;

Results: 4 and 0.

instr(text, search) returns the position of the first match. It returns 0 when there is no match, and NULL if an argument is NULL.

A zero result must be handled before extracting text relative to a delimiter.

Extracting an email domain

WITH cleaned AS (
    SELECT contact_id,
           NULLIF(lower(trim(email)), '') AS email_clean
    FROM practice_contact
)
SELECT contact_id,
       CASE WHEN instr(email_clean, '@') > 1
            THEN substr(email_clean, instr(email_clean, '@') + 1)
       END AS email_domain
FROM cleaned
ORDER BY contact_id;
1
Normalize spaces, ASCII case, and blank values.
2
Extract after @, with a basic guard for a missing username or delimiter.

This is extraction, not complete email validation.

trim(), ltrim(), and rtrim()

SELECT trim('  Ana  ') AS both_ends,
       ltrim('  Ana  ') AS left_only,
       rtrim('  Ana  ') AS right_only,
       trim('xyAnayx', 'xy') AS character_set;

character_set is Ana: the second argument is a set of characters, not a word or substring to remove.

By default, these functions remove ordinary spaces at the selected ends. They leave interior spaces and do not automatically remove every kind of whitespace.

Tabs, line breaks, and replacement

SELECT trim(char(9) || 'Ana' || char(10),
            ' ' || char(9) || char(10) || char(13)) AS clean;

SELECT replace('555-010-1001', '-', '') AS phone_digits;
1
Supply spaces, tabs, line feeds, and carriage returns explicitly.
2
replace(text, old, new) replaces every exact occurrence.

replace() is case sensitive. Repeated replacements can remove a known set of punctuation characters, but they do not validate a telephone number.

LIKE patterns

Pattern Meaning
'Love%' Starts with Love
'%Love%' Contains Love
'%Live' Ends with Live
'A_' A followed by exactly one character 
SELECT TrackId, Name
FROM Track
WHERE Name LIKE '%love%'
ORDER BY TrackId;

Default LIKE ignores ASCII letter case, but does not fully fold non-ASCII case.

Searching for literal % and _

SELECT TrackId, Name
FROM Track
WHERE Name LIKE '%!%%' ESCAPE '!'
   OR Name LIKE '%!_%' ESCAPE '!'
ORDER BY TrackId;
1
!% means a literal percent sign. The outer % symbols remain wildcards.
2
!_ means a literal underscore.

The classroom matches are 100% Live and Blue_Night.

Choose an explicit escape character so the pattern’s meaning is clear.

GLOB and regular expressions

SELECT TrackId, Name
FROM Track
WHERE Name GLOB '*[0-9]*'
ORDER BY TrackId;
1
* matches any sequence, and [0-9] matches one digit.
Operator Wildcards Case behavior
LIKE %, _ ASCII case insensitive by default
GLOB *, ?, [abc], [^abc] Case sensitive

REGEXP requires an application-defined function or extension. Stock SQLite does not supply a general regular-expression implementation.

Collations control comparison and sorting

SELECT CustomerId, LastName
FROM Customer
ORDER BY LastName COLLATE NOCASE, CustomerId;
Built-in collation Main behavior
BINARY Compares underlying encoded values
NOCASE Folds ASCII uppercase letters for comparison
RTRIM Ignores trailing ordinary spaces when comparing

A collation does not rewrite the stored text. NOCASE does not provide locale-aware multilingual ordering, and does not redefine LIKE behavior.

Formatting values for display

SELECT InvoiceId,
       printf('INV-%04d', InvoiceId) AS invoice_label,
       printf('$%.2f', Total) AS total_label
FROM Invoice
ORDER BY InvoiceId
LIMIT 3;
1
%04d formats an integer with at least four digits, padding with zeros.
2
%.2f formats a number with two decimal places.

The labels are text. Keep Total numeric for sums and numeric sorting. format() is an alias in SQLite 3.38+.

Combining rows with group_concat()

SELECT Country,
       group_concat(FirstName, ', ') AS customers
FROM Customer
GROUP BY Country
ORDER BY Country;
1
Join the non-NULL values from multiple rows into one string per group.

Without an explicit input order, the order inside the string is not guaranteed.

group_concat(DISTINCT Country) removes duplicates with the default comma separator. Deduplicate in a CTE when you also need a custom separator.

Ordered text aggregation · SQLite 3.44+

SELECT Country,
       group_concat(FirstName, ', '
                    ORDER BY FirstName, CustomerId) AS customers
FROM Customer
GROUP BY Country
ORDER BY Country;
1
This ORDER BY controls the order inside each joined string.

The outer ORDER BY controls the order of the result rows.

string_agg(value, separator) is an alias for the two-argument form of group_concat() in SQLite 3.44+.

CAST converts, but does not validate

SELECT CAST('007' AS INTEGER) AS number,
       CAST(7 AS TEXT) AS text_number,
       CAST('12abc' AS INTEGER) AS numeric_prefix,
       CAST('abc' AS INTEGER) AS nonnumeric;

Results: 7, ‘7’, 12, and 0.

SQLite can convert a numeric prefix or produce zero without reporting an invalid-number error. Validate an input’s structure before treating a successful cast as trustworthy.

Keep identifiers as text when leading zeros are meaningful.

A portable text workflow

  1. Preserve the original input.
  2. Convert documented blanks to NULL.
  3. Remove known unwanted spaces or punctuation.
  4. Normalize case only when appropriate for the field.
  5. Check structure before extracting components.
  6. Aggregate or join using the cleaned value.

Use a CTE to name intermediate results. Do not assume a new alias is available to another expression in the same SELECT list.

Storage, parsing, formatting, arithmetic, and intervals

A date, a timestamp, and a duration

Concept Example Interpretation
Calendar date 2024-02-29 A day on the calendar
Local date and time 2024-03-01 09:00:00 Needs a time-zone convention
Timestamp with offset 2024-03-01T09:00:00-08:00 An instant with an explicit offset
Duration 5400 seconds Elapsed time between instants

A birthday usually needs a date. An event log usually needs an instant.

Store track durations as numeric elapsed time, such as Track.Milliseconds.

SQLite has no dedicated date/time storage class

Representation Example Useful for
TEXT '2024-01-01 00:00:00' Readable timestamps in a fixed format
INTEGER 1704067200 Unix seconds since 1970-01-01 UTC
REAL 2460310.5 Julian day number and fractional days

Declaring a column DATE or DATETIME does not automatically parse or validate every value inserted into it.

Choose one representation, precision, and time-zone policy per column.

Supported input conventions

SELECT datetime('2024-03-01 09:30:00') AS spaced,
       datetime('2024-03-01T09:30:00Z') AS utc_text,
       datetime('2024-03-01T09:30:00-08:00') AS offset_text;

The first two give 2024-03-01 09:30:00. The third gives 2024-03-01 17:30:00.

Use supported, zero-padded year-month-day forms. SQLite does not parse every ISO 8601 variant or arbitrary locale format such as 03/01/2024.

Document the meaning of timestamps that have no offset.

Reformatting a documented import layout

WITH imported(raw_date) AS (VALUES ('03/25/2024'))
SELECT raw_date,
       substr(raw_date, 7, 4) || '-' ||
       substr(raw_date, 1, 2) || '-' ||
       substr(raw_date, 4, 2) AS candidate_iso_date
FROM imported;

This produces 2024-03-25 only because the source contract specifies MM/DD/YYYY with fixed widths.

03/04/2024 is ambiguous without that contract. Reshaping the string does not validate the resulting date. Apply the date-only round-trip check later in the lecture.

The date/time function family

Function Result type Example use
date() TEXT Calendar date
time() TEXT Time of day
datetime() TEXT Date and time
strftime() TEXT Custom format or date component
julianday() REAL Fractional-day arithmetic
unixepoch() INTEGER, or REAL with subsec Elapsed seconds
timediff() TEXT Calendar-aware difference, 3.43+

The first six accept modifiers. timediff(A, B) takes exactly two time values.

Extracting a date and a time

SELECT InvoiceId,
       date(InvoiceDate) AS invoice_day,
       time(InvoiceDate) AS invoice_time
FROM Invoice
ORDER BY InvoiceId
LIMIT 3;
1
Produce a normalized YYYY-MM-DD date.
2
Produce an HH:MM:SS time of day.

These expressions return derived values. They do not change InvoiceDate.

The current moment

SELECT CURRENT_DATE AS today_utc,
       CURRENT_TIME AS time_utc,
       CURRENT_TIMESTAMP AS timestamp_utc,
       datetime('now') AS also_utc;
  • The current-time keywords take no parentheses.
  • 'now' uses UTC and depends on when the query runs.
  • Repeated 'now' calls within the same SQLite step use the same instant.
  • A fixed reference date makes classroom outputs reproducible.

This lecture uses 2024-07-01 for historical customer-recency examples.

Unix seconds: explicit conversions

SELECT unixepoch('2024-01-01 00:00:00') AS seconds,
       datetime(1704067200, 'unixepoch') AS timestamp;
1
Convert a timestamp to integer Unix seconds: 1704067200.
2
Interpret the number as Unix seconds to reconstruct the timestamp.

For epoch milliseconds, divide by 1000.0 before using 'unixepoch'.

Avoid 'auto' when the unit is known. Small Unix-second values from early 1970 are ambiguous with Julian day numbers.

strftime(): formatting and extraction

SELECT InvoiceId,
       strftime('%Y-%m', InvoiceDate) AS year_month,
       strftime('%w', InvoiceDate) AS weekday_code,
       CAST(strftime('%H', InvoiceDate) AS INTEGER) AS hour
FROM Invoice
ORDER BY InvoiceId;
1
A sortable year-month grouping key.
2
Weekday code, with Sunday = 0 and Saturday = 6.
3
Convert the text component to a number when numeric operations need it.

%m means month. %M means minute.

Common strftime() codes

Code Meaning Example
%Y, %m, %d Year, month, day 2024, 02, 29
%H, %M, %S Hour, minute, second 09, 05, 07
%f Seconds including fraction 07.125
%j Day of year 060
%w Weekday, Sunday = 0 4
%W Week number, Monday-based, 00–53 09
%s, %J Unix seconds, Julian day as text Numeric-looking text
%% Literal percent sign %

An unsupported format code makes the result NULL. Month and weekday names need a mapping such as CASE or a lookup table.

ISO weeks can belong to a different year · 3.46+

SELECT strftime('%Y', '2021-01-01') AS calendar_year,
       strftime('%G-W%V', '2021-01-01') AS iso_week;
calendar_year iso_week
2021 2020-W53

Use %G with %V for an ISO week-year key. Combining %Y with %V can mislabel weeks near New Year.

%W and %U are different week-numbering systems and can include week 00.

Modifiers transform a time value

SELECT date('2024-02-28', '+1 day') AS next_day,
       datetime('2024-03-01 09:30:00', '+90 minutes') AS later,
       date('2024-03-15', 'start of month') AS month_start;

Results: 2024-02-29, 2024-03-01 11:00:00, and 2024-03-01.

Useful modifiers include signed days, hours, minutes, seconds, months, and years, plus start of day, start of month, and start of year.

Modifiers apply from left to right.

Calendar boundaries and modifier order

SELECT date('2024-02-15', 'start of month',
            '+1 month', '-1 day') AS month_end;

SELECT date('2024-01-31', 'start of month',
            '+1 month') AS next_month_start;
1
February 1 → March 1 → February 29.
2
January 1 → February 1.

Start from a known boundary before moving by months. Shifting January 31 directly can encounter a nonexistent target date.

Ambiguous month and year shifts · SQLite 3.46+

SELECT date('2024-01-31', '+1 month') AS default_shift,
       date('2024-01-31', '+1 month', 'floor') AS earlier,
       date('2024-01-31', '+1 month', 'ceiling') AS later;
default_shift earlier later
2024-03-02 2024-02-29 2024-03-02

February has no 31st. floor selects the earlier resolution and ceiling the later one. Default behavior uses ceiling.

Choose the rule that matches a billing, renewal, or anniversary policy.

Finding a weekday

SELECT date('2024-03-01', 'weekday 1') AS monday,
       date('2024-03-04', 'weekday 1') AS already_monday;

Both results are 2024-03-04.

For the portable weekday N pattern, use 0 = Sunday through 6 = Saturday. It advances to that weekday or stays on the date if it already matches.

It does not automatically skip holidays. Business-day schedules need a calendar table with explicit holiday rules.

Half-open date ranges

SELECT InvoiceId, InvoiceDate, Total
FROM Invoice
WHERE InvoiceDate >= '2024-02-01 00:00:00'
  AND InvoiceDate <  '2024-03-01 00:00:00'
ORDER BY InvoiceDate, InvoiceId;
1
Include the lower boundary.
2
Exclude the next period’s lower boundary.

This includes every February timestamp, including leap day. It avoids guessing the final second or fractional second of the month.

When text timestamp comparisons are reliable

Text order matches time order when values share:

  • A fixed, zero-padded format.
  • The same separator and precision conventions.
  • A common time-zone basis.

'2024-03-01T23:30:00-08:00' and UTC strings should be normalized before raw text comparisons.

A date-only upper bound such as <= '2024-02-29' excludes timestamps later that day. BETWEEN includes both endpoints, which can also cause boundary mistakes.

Elapsed time in days and seconds

SELECT julianday('2024-02-29 01:00:00')
       - julianday('2024-02-28 23:30:00') AS days,
       unixepoch('2024-02-29 01:00:00')
       - unixepoch('2024-02-28 23:30:00') AS seconds;
1
The elapsed interval is 0.0625 days.
2
The same interval is 5400 seconds, or 90 minutes.

Subtract end minus start. Divide seconds by 60.0, 3600.0, or 86400.0 to preserve fractional units.

Direct subtraction does not parse dates

SELECT '2024-03-01' - '2024-02-28' AS wrong_days,
       julianday('2024-03-01')
       - julianday('2024-02-28') AS elapsed_days;

Results: 0 and 2.0.

The subtraction operator converts the strings to numbers using their numeric prefixes. Both prefixes are 2024.

Convert timestamps to a numeric time representation before subtracting. There are two days here because 2024 includes February 29.

Calendar dates and completed 24-hour periods

SELECT julianday(date('2024-02-29 01:00:00'))
       - julianday(date('2024-02-28 23:30:00')) AS date_steps,
       (unixepoch('2024-02-29 01:00:00')
        - unixepoch('2024-02-28 23:30:00')) / 86400.0 AS elapsed_days;

Results: 1 calendar-date step and 0.0625 elapsed days.

Counted dates, completed days, and exact duration answer different questions. State the metric before choosing the calculation.

Floating-point Julian day differences can have small rounding errors.

timediff() gives a calendar-aware description · 3.43+

SELECT timediff('2024-03-15', '2024-02-15') AS span_a,
       timediff('2024-04-15', '2024-03-15') AS span_b;

Both results are +0000-01-00 00:00:00.000.

The spans contain 29 and 31 elapsed days. A calendar month has variable length.

Use julianday() or unixepoch() subtraction for numeric durations. timediff() has no modifier arguments, so convert Unix inputs first.

Subsecond precision · SQLite 3.42+

SELECT datetime('2024-03-01 09:00:00.125', 'subsec') AS stamp,
       unixepoch('2024-03-01 09:00:00.125', 'subsec') AS seconds;

subsec preserves the supported fractional output, currently milliseconds.

  • datetime() and time() normally show whole seconds.
  • unixepoch() normally returns integer seconds.
  • strftime('%f', ...) includes fractional seconds.
  • Preserve raw text or integer units if the application needs finer precision than the date/time functions provide.

From individual timestamps to defensible summaries

UTC offsets can change the calendar date

SELECT datetime('2024-03-01T23:30:00-08:00') AS utc_instant,
       date('2024-03-01T23:30:00-08:00') AS utc_date;

Results: 2024-03-02 07:30:00 and 2024-03-02.

The source’s local date is March 1. The UTC date is March 2.

Before grouping events by day, decide whose day the report means. An offset identifies the difference from UTC at that instant, not a complete named time-zone rule set.

localtime, utc, and daylight saving

SELECT datetime('2024-03-01 17:00:00', 'localtime') AS local_display;

The result depends on the host environment’s local time zone.

  • localtime converts a UTC value to the host’s local time.
  • utc is for an input that represents the host’s local time.
  • SQLite’s built-in modifiers do not accept named zones such as America/Los_Angeles.
  • A fixed offset does not encode daylight-saving transitions.

Store instants consistently in UTC. Use a time-zone-aware layer when reports require named-zone calendar rules.

Do not promise a particular output from this example. A hosted database tool can use UTC even if the student is in another zone. Repeated or skipped local clock times require more information than a naive timestamp.

Missing, unparseable, and normalized dates

SELECT datetime(NULL) AS missing,
       datetime('not a date') AS unparseable,
       date('2024-02-30', '+0 days') AS normalized;

The first two results are NULL. The final result is 2024-03-01.

A non-NULL result does not prove that the original text described a real date in the required format. SQLite can normalize impossible day-of-month values.

Use format checks, round-trip checks, and explicit business rules. Keep rejected raw values for review.

A round-trip check for date-only input

WITH inputs(raw_date) AS (
    VALUES ('2024-02-29'), ('2024-02-30'),
           ('2024-2-9'), (NULL)
)
SELECT raw_date,
       COALESCE(
         length(raw_date) = 10
         AND raw_date GLOB '[0-9][0-9][0-9][0-9]-[0-9][0-9]-[0-9][0-9]'
         AND date(raw_date, '+0 days') = raw_date,
         0) AS valid_date
FROM inputs;

Only 2024-02-29 passes. This check is specifically for canonical date-only strings, not arbitrary timestamps.

The pattern checks shape and the normalized round trip checks the calendar. The COALESCE converts an unknown result to 0. Add allowed year ranges and domain rules when needed.

Constraints need an explicit NULL policy

CREATE TEMP TABLE validated_date (
    event_date TEXT NOT NULL,
    CHECK (COALESCE(
        length(event_date) = 10
        AND event_date GLOB
            '[0-9][0-9][0-9][0-9]-[0-9][0-9]-[0-9][0-9]'
        AND date(event_date, '+0 days') = event_date,
        0))
);

A CHECK expression that evaluates to NULL does not fail by itself. NOT NULL and COALESCE(..., 0) make the intended rule explicit.

This demo creates a temporary table only. Use a deliberate migration to change a production schema.

A monthly revenue summary

SELECT strftime('%Y-%m', InvoiceDate) AS invoice_month,
       COUNT(*) AS invoice_count,
       ROUND(SUM(Total), 2) AS revenue
FROM Invoice
GROUP BY strftime('%Y-%m', InvoiceDate)
ORDER BY invoice_month;
1
Keep the year in the key so January from different years stays separate.

Solution 1 · NULL and empty strings

SELECT 'A' || NULL AS a,
       'A' || '' AS b,
       length('') AS c,
       COALESCE(NULLIF(trim('   '), ''), 'Unknown') AS d;
a b c d
NULL A 0 Unknown

An empty string is a known text value with zero characters. NULL represents an absent or unknown value. Concatenation propagates NULL, while concatenating an empty string adds no characters.

Solution 12 · Complete query

WITH metrics AS (
  SELECT c.CustomerId, c.FirstName || ' ' || c.LastName AS customer,
         lower(trim(c.Email)) AS email, COUNT(i.InvoiceId) AS n,
         ROUND(COALESCE(SUM(i.Total), 0), 2) AS spent,
         MAX(i.InvoiceDate) AS last_purchase
  FROM Customer c LEFT JOIN Invoice i
    ON i.CustomerId = c.CustomerId AND i.InvoiceDate < '2024-07-01 00:00:00'
  GROUP BY c.CustomerId, c.FirstName, c.LastName, c.Email
), recency AS (
  SELECT *, CAST(julianday('2024-07-01')
            - julianday(date(last_purchase)) AS INTEGER) AS days_since
  FROM metrics
)
SELECT CustomerId, customer,
       CASE WHEN instr(email, '@') > 1
            THEN substr(email, instr(email, '@') + 1) END AS domain,
       n AS invoice_count, spent AS total_spent, last_purchase, days_since,
       CASE WHEN n = 0 THEN 'Never purchased'
            WHEN days_since BETWEEN 0 AND 30 THEN 'Recent'
            ELSE 'Earlier' END AS segment
FROM recency ORDER BY total_spent DESC, CustomerId;

This supplied Customer data has well-formed email values. For dirty data, reuse the stronger structural checks from Activity 3. Keep unknown recency as NULL. The first CTE is the natural place to parameterize the snapshot date in an application.
