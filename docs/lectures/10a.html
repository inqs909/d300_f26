CASE WHEN in SQLite

Conditional logic

Motivation

Suppose the store wants every invoice labeled using these rules:

Invoice total Label
Less than 5 Small
At least 5 and less than 10 Medium
At least 10 Large

A CASE expression returns a value

CASE chooses a result according to conditions you supply.

SELECT InvoiceId, Total,
       CASE WHEN Total >= 10 THEN 'Large'
            ELSE 'Other'
       END AS invoice_size
FROM Invoice
ORDER BY InvoiceId;

CASE: conditions in each WHEN

CASE
    WHEN condition_1 THEN result_1
    WHEN condition_2 THEN result_2
    ELSE default_result
END AS column_alias

SQLite checks conditions from top to bottom and returns the result for the first true condition. If none is true, it uses ELSE. With no ELSE, the unmatched result is NULL. The END statement closes the expression

The syntax box is a template. Replace the placeholder names with actual expressions. Syntax and evaluation rules: https://sqlite.org/lang_expr.html#the_case_expression

Worked example: invoice sizes

SELECT InvoiceId, Total,
       CASE
           WHEN Total < 5 THEN 'Small'
           WHEN Total < 10 THEN 'Medium'
           ELSE 'Large'
       END AS invoice_size
FROM Invoice
ORDER BY InvoiceId
LIMIT 12;
1
An invoice below 5 receives Small.
2
Reaching this branch means the first condition was false. For nonmissing totals, this branch covers 5 up to, but excluding, 10.
3
Remaining nonmissing totals are at least 10.
4
Ends the case statemtn and names the column as invoice_size.

Simple CASE: compare one expression to values

SELECT CustomerId, Country,
       CASE Country
           WHEN 'USA' THEN 'US market'
           WHEN 'Canada' THEN 'Canadian market'
           ELSE 'Other market'
       END AS market
FROM Customer
ORDER BY CustomerId;
Form Good fit
CASE Country WHEN 'USA' ... Equality comparisons against one expression
CASE WHEN Total < 5 ... Ranges, multiple columns, or other conditions

Use searched CASE for comparisons such as <, >=, IN, or IS NULL.

Boundaries should leave no gaps

For nonmissing totals, our categories are:

Label Condition
Small Total < 5
Medium Total >= 5 AND Total < 10
Large Total >= 10

BETWEEN 5 AND 10 includes both 5 and 10. It would include the lower boundary of the Large category.

Branch order can change your answer

WITH examples(Total) AS (VALUES (12.00))
SELECT Total,
       CASE WHEN Total >= 5 THEN 'Medium'
            WHEN Total >= 10 THEN 'Large'
            ELSE 'Small'
       END AS incorrect_label,
       CASE WHEN Total >= 10 THEN 'Large'
            WHEN Total >= 5 THEN 'Medium'
            ELSE 'Small'
       END AS correct_label
FROM examples;

Testing category boundaries

Use a tiny VALUES table to test rules independently of the full database.

WITH test_values(Total) AS (
    VALUES (4.99), (5.00), (5.01), (9.99), (10.00), (10.01)
)
SELECT Total,
       CASE WHEN Total < 5 THEN 'Small'
            WHEN Total < 10 THEN 'Medium'
            ELSE 'Large'
       END AS invoice_size
FROM test_values

Conditions can involve several columns

SELECT InvoiceId, BillingCountry, Total,
       CASE
           WHEN BillingCountry = 'USA' AND Total >= 10
               THEN 'US large invoice'
           WHEN BillingCountry = 'USA'
               THEN 'US other invoice'
           WHEN BillingCountry IN ('Canada', 'Brazil')
               THEN 'Selected international market'
           ELSE 'Other market'
       END AS segment
FROM Invoice
ORDER BY InvoiceId;

Place the more specific US rule first. Use parentheses to make combinations of AND and OR clear.

NULL needs an explicit condition

WITH examples(Total) AS (VALUES (NULL), (4.99), (12.00))
SELECT Total,
       CASE
           WHEN Total IS NULL THEN 'Unknown'
           WHEN Total < 5 THEN 'Small'
           WHEN Total < 10 THEN 'Medium'
           ELSE 'Large'
       END AS invoice_size
FROM examples;
  • A comparison such as NULL < 5 produces an unknown result.
  • An unknown condition does not select a WHEN branch.
  • Use IS NULL to detect missing data.
  • In simple CASE, WHEN NULL also does not match a missing base value.

Missing text and blank text

NULL, '', and ' ' need different checks.

SELECT CustomerId, Company,
       CASE
           WHEN Company IS NULL THEN 'Missing'
           WHEN trim(Company) = '' THEN 'Blank'
           ELSE 'Present'
       END AS company_status
FROM Customer
ORDER BY CustomerId;

trim() removes ordinary spaces from both ends by default. A blank string is still a non-NULL value.

Result types and explicit defaults

Choose results that serve the same purpose in every branch.

SELECT TrackId, UnitPrice,
       CASE WHEN UnitPrice >= 1.00 THEN 1
            ELSE 0
       END AS premium_price_flag
FROM Track
ORDER BY TrackId
LIMIT 10;
  • A numeric flag works well for later calculations.
  • Text labels work well for categories and display.
  • Omit ELSE deliberately when you want unmatched rows to contribute NULL, as in some conditional aggregates.

Custom sorting with CASE

Suppose a report should list USA first, Canada second, and other countries alphabetically.

SELECT CustomerId, FirstName, LastName, Country
FROM Customer
ORDER BY CASE Country
             WHEN 'USA' THEN 1
             WHEN 'Canada' THEN 2
             ELSE 3
         END,
         Country, LastName, FirstName, CustomerId;

The numeric sort key does not need to appear in the output. Later sort terms resolve ties and make the order reproducible.

Reusing a category with a CTE

WITH labeled AS (
    SELECT InvoiceId, Total,
           CASE WHEN Total < 5 THEN 'Small'
                WHEN Total < 10 THEN 'Medium'
                ELSE 'Large'
           END AS invoice_size
    FROM Invoice
)
SELECT InvoiceId, Total, invoice_size
FROM labeled
WHERE invoice_size = 'Large'
ORDER BY Total DESC, InvoiceId;

The CTE names an intermediate result. Its new column is available to the outer query. This also avoids referring to a new alias elsewhere in the same SELECT list.

Grouping by a derived category

WITH markets AS (
    SELECT CASE Country
               WHEN 'USA' THEN 'USA'
               WHEN 'Canada' THEN 'Canada'
               ELSE 'Other'
           END AS market
    FROM Customer
)
SELECT market, COUNT(*) AS customer_count
FROM markets
GROUP BY market
ORDER BY customer_count DESC, market;

Conditional counting with SUM

SELECT BillingCountry,
       COUNT(*) AS invoice_count,
       SUM(CASE WHEN Total >= 10 THEN 1
                ELSE 0 END) AS large_invoice_count
FROM Invoice
GROUP BY BillingCountry
ORDER BY BillingCountry;

Each qualifying invoice contributes 1. Each other invoice contributes 0. SUM adds these values within each country.

The COUNT trap

WITH examples(Total) AS (VALUES (2.00), (12.00), (15.00))
SELECT
    COUNT(CASE WHEN Total >= 10 THEN 1 ELSE 0 END) AS wrong_count,
    COUNT(CASE WHEN Total >= 10 THEN 1 END) AS correct_count,
    SUM(CASE WHEN Total >= 10 THEN 1 ELSE 0 END) AS correct_sum
FROM examples;

COUNT(expression) counts nonmissing values, including 0. Without ELSE, nonqualifying rows yield NULL and are excluded by COUNT.

Conditional averages: the denominator matters

WITH examples(Total) AS (VALUES (2.00), (12.00), (18.00))
SELECT
    AVG(CASE WHEN Total >= 10 THEN Total END) AS qualifying_mean,
    AVG(CASE WHEN Total >= 10 THEN Total ELSE 0 END) AS zero_filled_mean
FROM examples;

AVG ignores NULL. For an average among qualifying invoices, omit ELSE. If none qualify, that conditional average is NULL.

Percentages from conditional counts

SELECT BillingCountry,
       COUNT(*) AS invoice_count,
       ROUND(
           100.0 * SUM(CASE WHEN Total >= 10 THEN 1 ELSE 0 END)
           / COUNT(*), 1
       ) AS pct_large
FROM Invoice
GROUP BY BillingCountry
ORDER BY pct_large DESC, BillingCountry;
  • The denominator is all invoices in that country.
  • 100.0 forces real arithmetic rather than integer division.
  • Every group here contains at least one invoice, so COUNT(*) is positive.

If working with a domain table and LEFT JOIN, count actual invoice IDs and consider NULLIF(COUNT(i.InvoiceId), 0) for a percentage with an invoice denominator. This differs from counting the placeholder row produced for a customer with no invoices.

Extension: categories from dates

SELECT InvoiceId, InvoiceDate,
       strftime('%Y', InvoiceDate) AS invoice_year,
       CASE
           WHEN CAST(strftime('%m', InvoiceDate) AS INTEGER)
                    BETWEEN 1 AND 3 THEN 'Q1'
           WHEN CAST(strftime('%m', InvoiceDate) AS INTEGER)
                    BETWEEN 4 AND 6 THEN 'Q2'
           WHEN CAST(strftime('%m', InvoiceDate) AS INTEGER)
                    BETWEEN 7 AND 9 THEN 'Q3'
           WHEN CAST(strftime('%m', InvoiceDate) AS INTEGER)
                    BETWEEN 10 AND 12 THEN 'Q4'
           ELSE 'Unknown'
       END AS quarter
FROM Invoice
ORDER BY InvoiceDate, InvoiceId;

strftime('%m', ...) returns text. CAST makes the numeric comparison explicit. Keep year in a quarterly report so different years remain distinct.

Optional extension. The Unknown label covers dates for which the month expression is NULL. An unparseable date should not silently become Q4. Date documentation: https://sqlite.org/lang_datefunc.html

Classifying a summary

WITH spending AS (
    SELECT CustomerId, SUM(Total) AS total_spent
    FROM Invoice
    GROUP BY CustomerId
)
SELECT CustomerId, ROUND(total_spent, 2) AS total_spent,
       CASE WHEN total_spent >= 45 THEN 'Gold'
            WHEN total_spent >= 35 THEN 'Silver'
            ELSE 'Bronze'
       END AS spending_tier
FROM spending
ORDER BY total_spent DESC, CustomerId;

Here we aggregate first, then classify each customer summary. Only customers with invoices appear in this query.

Keeping customers with no invoices

SELECT c.CustomerId, c.FirstName, c.LastName,
       COUNT(i.InvoiceId) AS invoice_count,
       COALESCE(SUM(i.Total), 0) AS total_spent
FROM Customer AS c
LEFT JOIN Invoice AS i
    ON i.CustomerId = c.CustomerId
GROUP BY c.CustomerId, c.FirstName, c.LastName
ORDER BY c.CustomerId;
  • LEFT JOIN preserves every customer.
  • COUNT(i.InvoiceId) counts actual invoices. COUNT(*) would also count the placeholder row for a customer with no match.
  • COALESCE(..., 0) replaces the missing sum with zero for a customer with no invoices.

The standard Chinook sample may have invoices for every customer. The query should still handle a new customer who has none. All selected nonaggregate columns appear in GROUP BY to keep grouping explicit.

A checklist for CASE queries

Before trusting a report, ask:

  1. Do the conditions represent the intended categories?
  2. Are cutoff values included in the right group?
  3. If conditions overlap, is the first match the intended one?
  4. What happens to NULL, empty strings, and unmatched values?
  5. Does an aggregate need zeros or missing values for nonmatches?
  6. Is the percentage denominator the population you intended?

Keep business rules visible. Test small examples before running a large report.

Solution 4

WITH customer_summary AS (
    SELECT c.CustomerId, c.FirstName, c.LastName,
           COUNT(i.InvoiceId) AS invoice_count,
           COALESCE(SUM(i.Total), 0) AS total_spent,
           SUM(CASE WHEN i.Total >= 10
                    THEN 1 ELSE 0 END) AS large_invoice_count
    FROM Customer AS c
    LEFT JOIN Invoice AS i ON i.CustomerId = c.CustomerId
    GROUP BY c.CustomerId, c.FirstName, c.LastName
), tiered AS (
    SELECT *, CASE WHEN invoice_count = 0 THEN 'No purchases'
                   WHEN total_spent >= 45 THEN 'Gold'
                   WHEN total_spent >= 35 THEN 'Silver'
                   ELSE 'Bronze' END AS customer_tier
    FROM customer_summary
)
SELECT CustomerId, FirstName, LastName, invoice_count,
       ROUND(total_spent, 2) AS total_spent,
       large_invoice_count, customer_tier
FROM tiered AS t;
