The SELECT Statement

The SELECT statement is used to pick the columns you want to see.

  • Basic Syntax:

    SELECT column1, column2
FROM table_name;

  • The Wildcard (Selects all columns):

SELECT * 
  FROM table_name;

The SELECT statement is the most common command. The asterisk is a wildcard, meaning “give me everything,” though it is often better practice to name columns specifically.

The DISTINCT Keyword

Sometimes a column contains many duplicate values. To see only unique values, use DISTINCT.

  • Syntax:

    SELECT DISTINCT column_name 
FROM table_name;

  • Example:

SELECT DISTINCT country 
    FROM customers;

DISTINCT is incredibly useful for seeing the unique categories or values within a specific column, like a list of countries where your customers live.

Filtering with WHERE

The WHERE clause is used to filter records based on specific conditions.

  • It acts as a gatekeeper.
  • If a row doesn’t meet the condition, it is excluded from the results.

Example:

SELECT * 
    FROM products 
    WHERE price > 50;

The WHERE clause is our primary tool for filtering. It allows us to isolate exactly the rows we need from a massive dataset.

Comparison Operators

Use these to compare values in your WHERE clause:

  • = (Equal to)
  • != (Not equal to)
  • > (Greater than)
  • < (Less than)
  • >= (Greater than or equal to)
  • <= (Less than or equal to)

These operators are the foundation of logical comparisons in SQL.

Logical Operators

You can combine multiple conditions using logic:

  • AND: Both conditions must be true.
  • OR: At least one condition must be true.
  • NOT: The condition must be false.

Example:

SELECT * 
    FROM users 
    WHERE age < 18 AND country = 'USA';

Logical operators allow for complex filtering. AND narrows your results, while OR expands them.

Sorting with ORDER BY

The ORDER BY clause is used to sort the result set.

  • Default: Ascending (A-Z, 1-10).
  • ASC: Explicitly for Ascending.
  • DESC: Explicitly for Descending (Z-A, 10-1).

Example:

SELECT name, salary 
    FROM employees 
    ORDER BY salary DESC;

Ordering helps us make sense of data by presenting it in a meaningful sequence, like highest salary to lowest.

Sorting Multiple Columns

You can sort by more than one column.

  • SQL sorts by the first column listed.
  • If there is a “tie” in the first column, it uses the second column.

Example:

SELECT last_name, first_name 
    FROM employees 
    ORDER BY last_name ASC, first_name ASC;

Sorting by multiple columns is very common when dealing with data that has many duplicate values in the primary sorting column.

Aggregation: The Big Idea

Aggregation is the process of performing a calculation on a set of values to return a single value.

  • Instead of seeing 1,000 individual sales, we want to see the Total Sales.
  • Aggregation “collapses” rows into summary statistics.

Aggregation turns “row-level” data into “summary-level” data. This is where data becomes “information.”

Common Aggregate Functions

  • COUNT(): Returns the number of rows.
  • SUM(): Returns the total sum of a numeric column.
  • AVG(): Returns the average value.
  • MIN(): Returns the smallest value.
  • MAX(): Returns the largest value.

These are the heavy lifters of data analysis. COUNT and SUM are perhaps the most frequently used in business reporting.

The GROUP BY Clause

When using aggregate functions, we often want to see the summary per category.

  • GROUP BY tells the database how to bucket the data.

Example:

SELECT department, COUNT(*) 
    FROM employees 
    GROUP BY department;

If you use an aggregate function and a regular column together, you MUST use a GROUP BY clause on that regular column.

The HAVING Clause

WHERE cannot be used with aggregate functions. For that, we use HAVING.

  • WHERE: Filters rows before they are grouped.
  • HAVING: Filters groups after they are aggregated.

Example:

SELECT category, AVG(price) 
    FROM products 
    GROUP BY category 
    HAVING AVG(price) > 20;

This is a common point of confusion. If you want to filter based on a calculation like “Average” or “Sum,” you must use HAVING.

WHERE vs. HAVING

Feature WHERE HAVING
Usage Filters Rows Filters Groups
Timing Before Grouping After Grouping
Aggregates Cannot use SUM(), AVG() Used with SUM(), AVG()

A good rule of thumb: If it’s a simple column condition, use WHERE. If it’s a condition on a summary calculation, use HAVING.

SQL Order of Execution

SQL is not read from top to bottom by the database engine. It follows a specific internal order:

  1. FROM (Pick the table)
  2. WHERE (Filter the rows)
  3. GROUP BY (Group the rows)
  4. HAVING (Filter the groups)
  5. SELECT (Pick columns)
  6. ORDER BY (Sort results)

Understanding this is the “secret sauce” to debugging complex queries. If your code is failing, it’s likely because you’re trying to use a column in the WHERE clause that hasn’t been selected yet!

SELECT FirstName, LastName, Country
FROM Customer
ORDER BY Country ASC, LastName ASC, FirstName ASC;

SELECT Name, UnitPrice
FROM Track
ORDER BY UnitPrice DESC, Name ASC;

Activity 4 Solutions

-- 1. Number of tracks in each genre
SELECT GenreId, COUNT(*) AS TrackCount
FROM Track
GROUP BY GenreId;

-- 2. Invoice count and total amount by country
SELECT BillingCountry,
       COUNT(*) AS InvoiceCount,
       SUM(Total) AS TotalInvoiced
FROM Invoice
GROUP BY BillingCountry;

-- 3. Average track length for each album
SELECT AlbumId, AVG(Milliseconds) AS AverageMilliseconds
FROM Track
GROUP BY AlbumId;

Activity 5 Solutions

-- 1. Countries with more than $100 in invoice totals
SELECT BillingCountry, SUM(Total) AS TotalInvoiced
FROM Invoice
GROUP BY BillingCountry
HAVING SUM(Total) > 100;

-- 2. Genres with more than 100 tracks
SELECT GenreId, COUNT(*) AS TrackCount
FROM Track
GROUP BY GenreId
HAVING COUNT(*) > 100;

-- 3. Countries with an average invoice total over $6.00
SELECT BillingCountry, AVG(Total) AS AverageInvoiceTotal
FROM Invoice
GROUP BY BillingCountry
HAVING AVG(Total) > 6.00;
